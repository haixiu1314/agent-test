# 第一阶段实施计划

本文件是实施计划，尚未执行。规则文档要求先完成环境检测，再经用户确认进入开发。

## 第一阶段目标

建立可真实运行的工程基础，打通“登录 → 创建项目 → 配置并连接一个受控 Agent → 保存版本”的最小业务闭环。完成 MySQL 与 Milvus 基础验证，为下一阶段真实 AI 能力做准备。

不在首阶段创建九个模块的空页面或空接口。后续模块有明确排期，不属于删减功能。

## 实施顺序

1. 复查现有目录和规则，建立 `.venv`；补齐 npm，验证 Python 依赖解析与前端生产构建。记录命令和精确版本，保留用户已有环境。
2. 配置管理采用环境变量；缺少关键配置时给出明确错误。日志包含请求关联 ID，并对密码、Token、Agent 请求头中的密钥脱敏。
3. 配置 MySQL 专用数据库，建立用户、项目、Agent、Agent 版本及操作日志表，统一 UUID 主键与创建/更新时间；通过 Alembic 创建和回滚迁移。
4. 实现注册、登录、JWT 认证、用户隔离及管理员权限基础。公开注册不能自行选择管理员角色。
5. 实现项目增删改查。跨用户访问不得泄漏资源；删除关联资源的规则必须明确，不能误删其他项目数据。
6. 实现 Agent 适配器接口、HTTP 请求模板、输入输出字段映射、超时与有界重试；Python 适配器只允许服务器注册的受控实现。密钥加密存储并在接口响应中隐藏。
7. 保存 Agent 配置版本快照，提供真实连接测试。先使用可控本地测试 Agent 验证协议；它只验证接入，不宣称完成最终 LLM 演示 Agent。
8. 建立中文登录、项目管理、Agent 配置界面，与真实后端连接。明确显示加载、空数据、错误和不可观测状态。
9. 完成 Milvus Standalone 配置、独立服务层和健康检查；运行插入、检索、删除临时向量的集成验证。元数据存 MySQL，向量存 Milvus。
10. 执行自动化测试、启动前后端、核查日志，修复问题，更新操作与学习文档，形成第一阶段验收报告。

## 验收条件

| 范围 | 必须取得的证据 |
| --- | --- |
| 环境 | 新虚拟环境 pip check 成功；精确依赖锁；npm 安装和前端 build 成功 |
| MySQL | 迁移成功；数据真实落库；重启服务后仍可查询；专用账号权限验证 |
| 认证 | 注册登录成功；错误密码、无效/过期 JWT 被拒绝；普通用户不能越权 |
| 项目 | 真实 CRUD，校验错误有统一格式；用户 A 无法操作用户 B 的项目 |
| Agent | 不同请求模板和字段映射有效；超时、非法响应和重试均可验证 |
| 密钥 | 数据库密文；前端/API 响应及日志不出现明文；缺失加密配置拒绝启动 |
| 版本 | 修改 Agent 后能查询历史版本，快照不随当前配置改变 |
| Milvus | 健康可用；真实写入、Top-K 检索和删除通过，保存执行证据 |
| 前端 | 登录、项目、Agent 主要流程通过 Playwright；界面状态与真实后端一致 |
| 可运行性 | Windows 启动脚本可重复执行；服务健康接口、OpenAPI 和日志核查通过 |
| 文档 | 初学者可依操作文档完成启动；学习文档说明实际文件与关键函数 |

不能预先承诺测试通过数量。实施后记录实际通过、失败、跳过数和原因。任何核心项未通过，第一阶段状态保持未验收，不进入下一阶段。
