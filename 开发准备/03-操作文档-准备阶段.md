# 操作文档（准备阶段）

目前只有开发前检测材料，没有可运行的 AgentTestLab 平台。本文教你查看环境和准备必要信息；随着开发推进，将补充安装、登录、接入 Agent、生成用例、执行测试和导出报告的实际操作。

## 查看本轮资料

从本目录的 README 开始，先看环境报告，再看第一阶段计划。不需要理解所有包名，优先关注 MySQL、Docker、npm 和模型配置四项。

## 重新运行只读检测

打开 PowerShell，在本文件所在目录执行：

```powershell
python .\check_environment.py
```

保存结果：

```powershell
python .\check_environment.py | Out-File -Encoding utf8 .\环境检测原始记录.json
```

检测会打印安装路径、包版本、本地端口和依赖问题，不安装依赖、不读出密钥、不修改服务。JSON 中 `null` 表示当前环境没有找到，端口 `true` 只代表网络连通，不能证明账号和业务功能可用。

## 准备数据库配置

当前 MySQL80 已运行。后续需要一个独立的 `agenttestlab` 数据库及项目账号；不建议直接使用 root 作为平台运行账号。知道现有管理员账号的人才能创建数据库和授权，开发过程不会猜测密码或改动已有业务库。

后续在项目提供的 `.env.example` 基础上生成本机 `.env`，再填写连接地址。不要把密码提交进 Git，也不要把真实密钥粘贴到聊天中。本阶段还没有生成可用的 `.env.example`。

## 准备 Docker 和 Milvus

先打开 Docker Desktop，确认它使用 Linux 容器，然后在普通 PowerShell 检查：

```powershell
docker version
docker compose version
docker info
```

`docker version` 只有 Client 信息并不够，必须看到 Server 信息。若出现管道访问被拒绝，检查 Docker Desktop 是否已启动、当前账号是否有使用 Docker 的权限，以及本机执行环境的访问限制。不要因一次权限报错就卸载 Docker。

Milvus 的 Compose 文件尚未开发，不要现在随意运行其他项目的容器配置。后续提供已锁定版本的启动脚本，并验证向量写入和检索。

## 准备模型信息

需要一个可用的聊天模型和一个 Embedding 模型，可以来自同一服务商，也可以不同。准备提供商、Base URL、模型名、超时设置及 API Key；密钥仅在本地配置中填写。

真实模型调用通常会产生费用。后续先用小批量验证配置，再执行批量用例与评估。没有模型配置时，只能验证独立于模型的功能，不能展示虚构的 AI 分数。

## 以后使用平台的大致顺序

环境准备 → 启动 MySQL/Milvus → 初始化数据库 → 启动后端和前端 → 注册登录 → 创建项目 → 配置模型与待测 Agent → 建立测试集 → 生成和审核用例 → 执行任务 → 查看轨迹/风险/报告 → 修改 Agent 后进行回归。
