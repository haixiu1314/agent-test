# 学习文档（准备阶段）

## 这个项目做什么

AgentTestLab 是“测试 AI 助手的平台”。例如一个企业助手能查知识、算数字、调用工具，平台会给它一组问题，检查它回答得对不对、工具用得对不对、会不会泄露信息，并保存过程供你复查。

平台和待测 Agent 是两个角色：平台负责出题、执行和评分，Agent 负责回答与执行自己的任务。内置企业知识助手只是其中一个待测对象，平台还要支持其他 HTTP Agent。

## 技术分别负责什么

| 技术 | 浅显解释 | 在本项目的任务 |
| --- | --- | --- |
| Vue 3 | 构建网页界面的框架 | 项目列表、配置表单、测试结果页 |
| TypeScript | 给 JavaScript 增加类型约束 | 提前发现前后端字段不一致 |
| Vite / npm | 构建工具 / 包管理工具 | 安装前端依赖、开发与打包 |

| MySQL | 保存结构化业务记录的数据库 | 用户、项目、用例、任务、结果 |
| Milvus | 根据向量相似度检索文本的数据库 | 从知识库找语义相关内容 |

## 为什么需要前后端分离

网页负责“把操作展示给你”，后端负责“真正完成业务”。比如点击“创建项目”：Vue 收集名称，Axios 发送 HTTP 请求，FastAPI 验证登录及字段，ProjectService 执行业务，SQLAlchemy 写入 MySQL，再把新项目返回网页。

输入可以是 `{"name":"企业助手测试","description":"验证工具调用"}`；输出应包含真实落库后的项目 ID、名称和创建时间。具体字段会在第一阶段写入 OpenAPI，此例不是已实现的接口契约。

只让网页显示“创建成功”却不保存数据库，刷新后数据消失，这不算完成。

## 为什么 MySQL 和 Milvus 都需要

MySQL 擅长回答“这个用户有哪些项目”“任务执行到哪一步”。Milvus 擅长回答“哪些知识片段和这个问题意思相近”。文本经过 Embedding 模型变成一串数字，也就是向量，Milvus 根据向量距离检索。

向量接近不等于事实冲突。“保修一年”和“保修两年”可能相近，但还要判断是不是同一个产品、同一时期、同一政策。平台必须通过事实分析和模型判断再记录冲突，不能仅根据相似度判定。

## 为什么要三种评估结合

规则适合验证明确条件，比如调用了哪个工具、参数是否正确、响应是否超时。LLM Judge 适合理解语义，但它也可能判断错误。DeepEval/RAGAS 提供专业指标，也仍依赖输入质量、模型和配置。

因此每次评估要保存依据、配置和异常，保留人工复核机会。对于工具测试，最终回答正确也不能掩盖调用了错误工具的问题。

## 什么是执行轨迹

轨迹是系统实际观察到的事件：输入、检索结果、工具名、参数、工具返回、最终回答、异常与耗时。它能帮助你定位“工具选错”还是“参数提取错”。

平台不能读取模型内部完整思维过程。某个外部 Agent 不提供工具事件时，应显示“不可观测”，不能自行编故事补齐轨迹。

## 为什么单独建立虚拟环境

虚拟环境像给项目准备一个独立工具箱。当前 Anaconda 装了许多其他软件，pip check 已发现六项依赖冲突。项目使用 `.venv` 后，可以选择和固定自己的版本，避免影响 Gradio、Streamlit 或其他现有项目。

“锁版本”指记录精确版本和依赖组合。只有安装、依赖检查、实际测试通过，才能把它当作兼容方案。某个包已经装好或能导入，不代表它所有功能都可靠。

## 本轮实际代码在哪里、怎样工作

本目录 `check_environment.py` 是实际可运行代码；计划中的后端、前端模块尚未创建。

- `main()`：组织全部检测，将结果输出为 JSON。
- `MemoryStatus`：Windows 内存结构体，通过只读系统 API 获取内存，补充权限受限的 CIM 检测。
- `shutil.which()`：查询命令路径，只检查当前工具搜索路径。
- `importlib.metadata.version()`：读取当前解释器已安装的包版本。
- `importlib.import_module()`：验证若干关键模块能否加载，逐项保留异常。
- `socket.connect_ex()`：尝试连接本地常见服务端口，使用短超时，不执行数据库或模型业务。
- `subprocess.run()`：执行当前 Python 的 `pip check`，保存依赖一致性结果。

输入：当前电脑环境，不需要用户密码或 API Key。输出：JSON，包含路径、版本、端口布尔值、导入状态和依赖冲突。它不会自动安装软件或修复冲突。

运行：`python .\check_environment.py`。在编辑器中可以给 `main()` 内的循环设置断点，观察每个包或端口的结果。

## 常见问题

| 现象 | 解释与排查 |
| --- | --- |
| 找不到 npm | Node 可执行文件与 npm 不总是一起出现在当前运行环境；先检查完整工具链 |
| Docker 客户端有版本但无法启动容器 | 客户端与引擎不同；检查 Desktop、Linux 容器、WSL2 和访问权限 |
| 3306 连通但登录失败 | 网络可连接不代表账号正确；检查专用账号、密码、数据库和权限 |
| pip check 报错 | 已装包对依赖版本要求不一致；优先在新虚拟环境解决 |
| 模型输出 JSON 解析失败 | 模型可能输出额外文字或不符合 schema；后续需结构化输出、验证及有界重试 |
| RAG 分数很低 | 可能是文档质量、检索、问题集或生成问题；结合原始样本和轨迹定位 |

建议先理解“网页 → 接口 → 服务 → 数据库”的流程，再学习适配器、异步任务、Embedding 和评估指标。每个开发阶段都会用实际文件和函数补充本学习文档。
