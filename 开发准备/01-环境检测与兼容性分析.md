## 技术兼容性方案

- **Python：** 优先试用现有 3.12.7 创建 `.venv`，避免修改系统解释器。DeepEval/RAGAS/pymilvus 必须一起解析依赖并实测；若缺少 Windows 3.12 可用轮子，再评估独立 Python 3.11 环境，不能提前声称需要降级。
- **后端：** FastAPI 与 Pydantic 2、SQLAlchemy 2 配套使用，API 模型和数据库模型分层。Alembic 管理数据库迁移。
- **AI 依赖：** LangChain、langchain-openai、langgraph、RAGAS、DeepEval 的传递依赖容易交叉冲突。在新环境进行一次完整解析，再固定精确版本；不能把现有版本表当成已通过验收的依赖锁。
- **MySQL：** 优先复用 MySQL80，新建专用数据库和最小权限账号，使用 utf8mb4。项目正常运行必须使用 MySQL，不将 SQLite 替换成生产存储。
- **Milvus：** 本地 Docker Standalone；先核实 Linux 容器、WSL2、可用资源，再锁定 Milvus/etcd/MinIO 镜像组合和 pymilvus 客户端版本。建议至少为容器预留约 4 核 CPU、8 GiB 内存和 20 GiB 磁盘，此处为工程预算，最终以所选版本要求及实测为准。
- **前端：** Vue 3 + TypeScript + Vite；补齐完整 Node 工具链后，核对所选 Vite 的 engines 要求，执行安装与生产构建。固定 package-lock.json。
- **专业评估：** 需提供可用的聊天模型及 Embedding 配置；必须实测结构化输出、工具调用和向量维度。评估过程保留原始记录、模型配置和异常。
- **测试：** Pytest 验证后端；Playwright 验证浏览器操作；Postman 交付接口调试集合；JMeter 验证平台 API 压力。Agent 响应性能与平台接口压力分别记录。

本轮未联网解析包、未下载安装，因此不提供未经验证的“最终兼容版本锁”。第一阶段必须产出精确版本锁及验证证据。
