# 第二阶段实施计划

2026-11-02。用户已明确要求“继续下一阶段”，因此开始第二阶段；第一阶段 Milvus 验证仍保留为环境阻塞，不改写历史验收结果。

目标：真实持久化的测试集与结构化用例管理、人工编辑、筛选与分页、JSON/CSV 导入导出；统一 LangChain 模型服务、可审计的结构化 AI 用例生成；带真实模型调用、受控计算/天气工具和多轮历史的企业助手演示基础。

实施顺序：检查已有代码与依赖 → 建立数据库迁移及输入输出契约 → 用例管理与版本快照 → 模型配置与生成记录 → 演示 Agent → 中文界面 → Pytest/MySQL/浏览器验证 → 实际模型验证（需本地配置）→ 查日志、修复和文档。

新增表：test_suites、test_suite_versions、test_cases、model_configs、generation_runs、demo_runs。用例生成先形成待审阅草稿，用户确认保存后才进入测试集。生成失败、模型超时和结构错误保留明确状态，不用静态用例冒充模型结果。演示输入、回答和事件加密留存，天气与知识样例明确标注。

核心验收：跨用户隔离、原子导入、用例版本检查、测试集快照、导出往返、密钥无回显、真实模型调用与结构化输出、生成记录与保存关联、演示工具/历史事件、主要页面浏览器流程。自动化测试中的模型替身必须明确标注，与真实模型验收分开记录。

本阶段不实现第三阶段的批量任务执行/评估，也不将本地 JSON 演示知识片段冒充 Milvus RAG。文档检索、向量化和 RAGAS 仍属于第四阶段。
