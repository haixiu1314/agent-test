# 比赛技术方案与测试计划

2026-11-04。项目是面向不同Agent的测试工具，不绑定企业助手这一种业务。企业助手只作为可控演示目标，HTTP适配器支持真实外部协议，受控Python适配器不接受任意上传代码执行。

## 技术方案

FastAPI负责鉴权、参数契约与接口，LangChain负责模型和工具调用；MySQL保存业务关系、历史和证据；Milvus保存向量检索数据。Pytest验证业务与异常，Playwright验证真实浏览器，Postman用于人工接口调试，JMeter承担基础并发检查，DeepEval和RAGAS分别评估回答与RAG。

前端Vue3/TypeScript/ElementPlus提供项目、Agent、用例、任务、知识库、安全、轨迹、报告与管理页面；VueFlow呈现已观测关系，ECharts呈现真实结果状态。Pandas/Matplotlib生成可导出的分析图。

相对于普通聊天演示，技术价值在于结构化用例与评估器匹配、不可变版本快照、工具证据与语义混合判断、知识质量和检索生成联查、同源用例回归、可解释缺失维度评分。可观测行为覆盖不是读取模型私有思维链。

## 验证层次

| 层次 | 验证对象 | 证据与界限 |
| --- | --- | --- |
| 快速业务测试 | 校验、权限、状态机、异常、算法契约 | SQLite/模型替身不代表真实MySQL或AI |
| 真实基础服务 | HTTP协议、MySQL迁移/行锁/持久化/加密 | 与本机独立3307实例实际交互 |
| UI端到端 | 用户点击、下载、图表、响应式与历史 | 真实浏览器、API、MySQL；测试目标非AI |
| 专业算法 | DeepEval、RAGAS实际库代码 | 有本地协议替身算法测试，不能替代模型效果 |
| 真实模型和向量 | 模型生成、工具循环、语义、安全、Embedding/Milvus/RAGAS | 当前环境阻塞，配置后补跑真实脚本并人工抽查 |
| 基础负载 | readiness并发与延迟 | 已提供JMX，当前JMeter未执行 |

## 现场演示建议

1. 先展示项目和Agent接入、当前库位置，避免只展示静态页面。
2. 已配置模型时生成20–30条用例，人工审阅入套件。
3. 执行正常任务与故意错误任务，展示原始响应和失败依据。
4. 上传重复/一年两年冲突知识，真实索引后展示来源和RAGAS样本。
5. 展示隔离安全目标的禁止工具证据，再展示语义安全评估；模型结果需人工抽查。
6. 在轨迹中定位工具、参数、异常，明确不可观测部分。
7. 选择相同测试集的V1/V2任务，定位新增失败，导出完整报告。

缺少真实模型或Milvus时，只能演示对应非模型验证，现场不能把协议回显、模拟天气或人工向量包装成AI效果。所有最终签字以《全功能操作与验收手册》的实际记录及《最终开发与验收报告》为准。
