## 2. 不配置模型，先完成第一条测试用例

1. 在“测试项目”创建项目，例如“企业助手测试”。
2. 打开“测试用例”，选择该项目，点击“创建套件”，输入“基础问答”。套件就是一组用例的容器。
3. 点击“新增用例”，名称填“普通问候”，类型选“功能”，优先级选 P1。
4. 场景填“新用户首次问候”，用户输入填“你好”。
5. 预期行为填“礼貌回应并说明可提供的帮助”，预期结果填“包含问候语，不编造业务事实”。
6. 默认 JSON 中的 `rubric` 是判定说明，可以保留或修改；需要关键词时在 `must_include` 填入字符串。
7. 点击“保存用例”。刷新页面后仍能看到，说明数据已保存到 MySQL。
8. 修改用例名称，再打开“版本记录”，可查看修改前后的套件快照。

本阶段只保存判定规则，**尚不执行这些规则，也没有评分结果**。DeepEval、RAGAS 和批量执行属于后续阶段。

## 3. 判定规则怎么填

最简单的功能用例高级字段：

```json
{
  "history": [],
  "rules": {
    "evaluators": ["rules"],
    "rubric": "包含礼貌问候且不编造业务事实",
    "must_include": ["你好"],
    "must_not_include": []
  },
  "tags": ["基础功能"]
}
```

`history` 是本条用例带入的历史对话；`rules` 是未来执行时使用的判定依据；`tags` 方便分类。所有引号必须是英文双引号，最后一个字段后不能加逗号。

| 类型 | 必填依据 |
| --- | --- |
| 工具 tool | `evaluators` 包含 `tool_trace`；填写 `expected_tool`、按需填写 `expected_arguments`；两个 `require_*` 都为 true |
| 记忆 memory | `history` 不为空；`evaluators` 包含 `conversation` |
| 安全 security | `evaluators` 包含 `security_policy` 和 `llm_judge`；填写 `security_policy` |
| RAG rag | `evaluators` 包含 `ragas`；建议填 `reference_contexts` |

工具用例的 `rules` 示例：

```json
{
  "evaluators": ["tool_trace"],
  "rubric": "调用 calculator，表达式为 (125+75)/4，成功取得结果 50，并据此回答",
  "expected_tool": "calculator",
  "expected_arguments": {"expression": "(125+75)/4"},
  "require_tool_success": true,
  "require_output_uses_tool": true
}
```

这比“回答包含 50”更严格：答案碰巧正确，不能证明工具被正确调用。可导入 `docs/examples/人工用例模板.json` 学习四种完整写法；这些模板是人工示例，不是模型生成结果。

## 4. 导入与导出

在套件内点击“导入 / 导出”。优先使用 JSON：先导出已有用例，再按同样字段编辑，或选择本地文件读取。每批 1–100 条；文件最多 800 KB，实际请求还受 1 MiB 总体限制。大文件请分批。

导入前会验证整批数据，有一条不合法就全部不写入。导入采用新增方式，相同名称不会自动覆盖，也不会去重。导入的来源标为“文件导入”，不能通过文件伪造“AI 生成”来源。

CSV 的每个单元格使用 JSON 编码：普通文字也需要 JSON 字符串引号，列表和对象保留为 JSON。该格式支持中文、换行和嵌套规则往返，并避免把以 `=` 开头的名称当成表格公式。请以平台导出的 CSV 为模板；普通 Excel 随意另存的 CSV 不一定符合此格式。

套件最多 1000 条用例，快照最多 4 MiB；导出的完整大套件可能需要拆成多个不超过 100 条的批次导入。

## 5. 稍后配置真实模型

方式一：编辑项目根目录 `.env`，仅填写以下字段，保留原有数据库、JWT 和加密配置：

```dotenv
LLM_BASE_URL=https://你的服务商接口地址/v1
LLM_MODEL=服务商提供的聊天模型名称
LLM_API_KEY=仅在本机填写的密钥
LLM_TIMEOUT_SECONDS=60
```

接口需兼容聊天 completions；企业助手还需要模型支持工具调用。填写后重启后端，页面刷新后查看环境配置状态。“已填写”仅代表字段存在，实际连通性由真实调用确认。调用会使用服务商额度，密钥不要发到聊天中。

方式二：在页面保存多套模型配置。注册账号默认是 tester；机器所有者可在本地执行：

```powershell
cd E:\Project-xhb\ai-test
.venv\Scripts\python.exe scripts\promote_admin.py 你的已注册用户名
```

刷新后在“模型配置”添加服务地址、模型名和密钥，用途选 `generation` 或 `demo`。两种用途可分别建配置。密钥在数据库加密保存且不会回显；编辑时留空保留原值。普通账号可使用全局配置，但不能修改。`judge/security/rag/embedding` 是为后续模块预留的配置用途，当前没有对应评估流程。

## 6. AI 生成与审阅

1. 选择项目和生成模型，填写具体业务需求。
2. 勾选要覆盖的类型，用例数量至少等于类型数量。
3. 可展开附加信息，粘贴或读取 TXT/Markdown 系统提示词，并填写 JSON 工具列表和接口说明。
4. 点击“调用模型生成草稿”。模型需返回能力分析、风险和结构化用例。
5. 生成成功后逐条展开检查、修改 JSON，取消不需要保存的草稿，选择目标套件。
6. 点击“保存选中的审阅用例”。只有此时用例才入库，并关联生成记录。

已经保存的草稿不能重复入库。修改已入库用例请到“测试用例”页面。生成失败不会自动换成预置用例，也不会自动重试付费请求；可查看错误码后自行重试。

## 7. 企业助手演示

选择项目和 demo 模型，尝试“计算 (125+75)/4”“年假如何申请”“北京天气如何”。成功后右侧显示真实模型响应与工具执行事件，对话历史会在下一轮传入模型；可清空本轮上下文。输入、回答和事件以加密方式保存到运行记录中。

计算器只支持受控四则运算，不能执行 Python 代码。天气是固定模拟结果；制度来自两条本地样例，使用关键词匹配，**不是 Milvus 向量 RAG**。缺陷实验可选择错误工具描述、缺失知识、冲突知识、不合理提示词或工具超时，用于后续评估模块的测试。系统提示词中的安全要求不等于经过验证的安全保障。

浏览器测试需先运行 8000 后端和 5173 前端，并保持模型未配置以验证缺配置路径；会创建带验收前缀的账号和项目。测试替身不代表真实模型通过。

配置 `.env` 后可运行真实 AI 验收（会产生真实模型调用并保留验收数据）：

```powershell
cd E:\Project-xhb\ai-test
.venv\Scripts\python.exe scripts\verify_real_model.py
```

无配置时脚本返回 `blocked`、退出码 2；配置存在时会检查八类生成用例、草稿保存和真实计算器事件。通过也仅代表本次样本，不代表全面质量或安全性通过。

| 现象 | 处理 |
| --- | --- |
| 409：版本已变化 | 刷新套件/用例后重新编辑，避免覆盖他人修改 |
| 422：输入格式错误 | 检查 JSON、必填文本、测试类型要求；导入时先用模板试一条 |
| model_not_configured | 填写 `.env` 后重启，或选择已有模型配置 |
| invalid_structured_output | 模型未返回合法结构，或数量/覆盖类型不符；简化需求、降低数量或更换模型 |
| model_call_failed / 502 | 检查服务商地址、模型权限、余额、工具支持和网络；客户端不会回显上游敏感异常 |
| 429：模型忙碌 | 当前版本单进程只接受一个生成/演示请求，稍后重试 |
| 503：数据库错误 | 查看 `.local/backend.log`、`.local/mysql-error.log`，确认独立 MySQL 已启动、迁移为 head |
| 提示先删关联内容 | 项目仍有套件/Agent；有生成或演示审计记录的项目暂不提供删除 |

后端日志只记录请求号、方法、状态和耗时，不记录密钥、请求体或上游异常原文。重启后未完成的生成/演示会标为失败，当前只支持单进程，勿配置多个 Uvicorn worker。

后端和前端窗口按 Ctrl+C 停止。只需停止项目数据库时执行 `.venv\Scripts\python.exe scripts\stop-mysql.py`；不要停止原有 MySQL80 服务。不要删除 `.env` 的 `ENCRYPTION_KEY`，否则既有密文无法解密。
