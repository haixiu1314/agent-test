# 学习文档：从网页到真实数据库

适用版本：0.1.0。建议先按操作文档创建一个自己的项目，再对照代码阅读。

## 先理解这次做成的事情

第一阶段实现的是平台基础：你能注册、登录、保存项目、接入 Agent、验证协议、查询配置版本。现在并没有 AI 用例生成或 RAG 评估，回声适配器也没有调用模型。

核心调用关系：

```text
浏览器 Vue 页面
  → Axios 发送 /api/v1 请求
  → FastAPI 校验输入 + JWT
  → 业务层检查项目归属
  → SQLAlchemy 写入 MySQL
  → 响应模型过滤公开字段
  → Vue 更新列表
```

连接测试额外经过：解密当前 Agent 配置 → 选择适配器 → 调用真实目标 → 检查返回字段 → 保存审计记录 → 返回协议检查结果。

## 前端从哪里读

| 文件 | 作用及关键函数 |
| --- | --- |
| `frontend/src/main.ts` | 创建 Vue 应用、注册 Element Plus 和路由；未登录时转向登录页 |
| `frontend/src/App.vue` | 左导航、工作空间、退出登录；移动端菜单折叠 |
| `frontend/src/api.ts` | Axios 实例；自动加入 JWT；`message()` 将统一错误显示为中文提示 |
| `frontend/src/views/Login.vue` | `submit()` 注册或登录，成功后保存当前会话 Token |
| `frontend/src/views/Projects.vue` | `load/open/save/remove()` 查询、编辑、保存和删除项目 |
| `frontend/src/views/Agents.vue` | `save()` 组装配置；`connect()` 验证连接；`showVersions()` 查询快照 |
| `frontend/src/views/System.vue` | `check()` 分别查询服务存活和数据库就绪情况 |
| `frontend/src/style.css` | 统一色彩、间距、响应式布局 |
| `frontend/src/controls.css` | 控件点击、长对话框滚动与减少动画的辅助规则 |

Vue 中 `ref()` 表示会驱动界面更新的数据。例如 `items.value` 接收到数据库返回的项目数组后，模板中的 `v-for` 自动重新渲染。

TypeScript 的 `Project` / `Agent` 接口在 `api.ts` 中定义前端字段。后端也有同名意义的响应模型。两边字段必须一致；如果前端读 `projectName`，后端返回 `name`，页面就会错误。

## 后端如何启动

`backend/app/main.py` 的 `create_app()` 是应用工厂：读取配置，创建数据库连接池、会话工厂和密钥保险库，安装中间件，注册路由。

命令中的 `app.main:create_app --factory` 表示让 Uvicorn 调用这个函数创建应用。开发时不会自动建表；表结构由 Alembic 明确迁移，这样升级过程才可追溯。

输入：`.env` 环境变量。输出：FastAPI ASGI 应用，监听本机 8000 端口。日志配置在 `backend/logging.json`。

## 一个“创建项目”请求怎样完成

1. `Projects.vue` 的 `save()` 读取表单，发送 `POST /api/v1/projects`。
2. `api.ts` 加入 `Authorization: Bearer ...`。
3. `routes.py` 中的 `current_user()` 验证 Token，查到真实用户。
4. `ProjectInput` 校验名称长度、空白和未知字段。
5. `create_project()` 创建 ORM 对象并写入数据库，`log_operation()` 同时加入审计记录。
6. `db.commit()` 让项目和日志一起提交。失败时不会返回虚假的成功。
7. `ProjectPublic` 只输出允许公开的字段。
8. 网页重新加载列表，拿到刚刚创建的数据库记录。

示例输入：

```json
{"name":"企业助手测试","description":"验证工具协议","business_type":"知识问答"}
```

示例输出字段：`id`、`name`、`description`、`business_type`、`created_at`、`updated_at`。ID 为服务端生成的 UUID；具体真实记录以你的页面为准。

## 为什么要分 models、schemas 和 services

- `models/entities.py` 描述数据库表，包含需要保存的密钥密文、密码哈希等。
- `schemas/inputs.py` 描述哪些输入允许进入系统。
- `schemas/outputs.py` 描述哪些字段可以返回给网页。
- `services/catalog.py` 集中处理资源归属、分页、序列化和版本快照。
- `api/v1/routes.py` 组织认证、HTTP 路由和事务边界。

不要把数据库对象整个转换为 JSON 返回。否则未来多加一个敏感字段时，可能无意中暴露给网页。独立响应模型能减少这种风险。

## 数据库、会话和事务是什么

`db/session.py` 的 `make_engine()` 创建数据库连接池，并明确拒绝用 SQLite 作为生产存储。`make_sessions()` 创建用于每次请求的会话。

事务可以理解为“一组一起成功或一起放弃的写入”。保存 Agent 时，当前配置、版本快照和审计日志在同一事务中提交。某一项失败，不能只保存一半。

当前五张业务表：`users`、`projects`、`agents`、`agent_versions`、`operation_logs`。`alembic_version` 是迁移工具自己的版本表，不是业务模块。

`migrations/versions/0001_foundation.py` 的 `upgrade()` 创建本阶段结构，`downgrade()` 撤回该结构。降级会删除这些表，因此只在临时测试库验证，不能在已有业务数据的库中随意执行。

## 身份认证与数据隔离

JWT 是带签名和有效期的登录凭证，不是加密数据库。后端在 `core/security.py` 的 `issue_token()` 签发 Token，`read_token()` 验证签名、签发方、接收方和过期时间。

验证身份之后还要检查权限。`project_for_user()` 检查项目是否属于当前用户；`agent_for_user()` 先找 Agent，再检查它的所属项目。用户 A 不能只靠猜到用户 B 的 ID 访问其资源，越权资源统一返回 404。

公开注册只能创建 tester。管理员提升只能通过本地脚本完成。认证接口还有单来源 15 次/分钟的开发期进程内限流；未来多进程部署时必须使用共享存储限流，不能把它当作完整生产防护。

## 密码为什么哈希，Agent 密钥为什么加密

登录密码只需要判断“是否相同”，不需要取回原文，所以 `hash_password()` 使用随机盐和 scrypt 保存不可逆结果。`verify_password()` 重新计算并作常量时间比较。

Agent API Key 后续调用时必须取出使用，因此 `SecretVault.encrypt/decrypt()` 用 Fernet 对称加密。`ENCRYPTION_KEY` 只保存在本机环境配置；数据库泄漏时，密文不会直接变成可用密钥。

两个限制要理解：环境配置本身仍需保护；丢失加密密钥会导致旧密文无法恢复。不要在已经保存 Agent 后随意重新生成它。

错误校验只返回字段位置和错误类型，不回显密码或请求头的原始输入。日志只记录 request_id、方法、状态和耗时，不记录认证值或上游响应体。

## 适配器模式解决什么问题

不同 Agent 可能把输入命名为 `input`、`question` 或 `payload.question`，输出也可能在 `data.answer`。平台不能要求别人改成同一种接口。

`adapters/base.py` 的 `AgentAdapter.invoke()` 是内部统一入口，输入是用户文本与历史数组，输出是 `AgentResponse`。

`adapters/http.py`：

- `set_field()` 将统一输入写入配置中的嵌套对象。
- `get_field()` 从目标 JSON 中读取最终字符串回答。
- `HttpAgentAdapter.invoke()` 根据方法发送请求，限制超时与响应大小，执行有界重试。
- `AdapterError` 把上游异常转换成稳定错误码，避免暴露上游密钥或原始错误页。

`adapters/local.py`：只接受明确注册的适配器名。当前 `ProtocolEchoAdapter` 返回协议回声，用来验证接入，不能执行上传代码、任意模块导入或模型推理。

## 版本快照怎样防止被覆盖

`Agent.version` 是当前序号，`AgentVersion.snapshot` 保存当时的公开配置，另有独立的密钥密文。

编辑时网页把 `expected_version` 一起提交。后端对当前记录加数据库行锁，检查预期序号。如果已被其他页面更新，则返回 409，提示刷新。新版本提交不会修改旧快照。

删除 Agent 会删除它的配置版本，但保留操作审计。项目包含 Agent 时拒绝删除，让用户明确处理关联关系。

## MySQL 与 Milvus 的边界

`integrations/milvus.py` 是独立向量服务层，提供创建分块集合、插入、检索及按文档删除向量的方法。字段按原需求保留来源、页码和元数据。

目前只有服务层及验证脚本，还没有文档上传、真实 Embedding 与 RAG 业务。`verify_milvus.py` 使用人工四维向量验证协议，不是语义检索演示；本轮执行因 Milvus 不可连接而失败。

后续每个文档的业务记录放 MySQL，文本向量放 Milvus，两者删除与失败补偿要一起设计。

## 运行、断点和排错

先依操作文档启动。学习时可以在编辑器中给 `create_project()`、`project_for_user()`、`HttpAgentAdapter.invoke()` 设置断点，观察输入模型、用户 ID、转换后的参数和输出。不要将包含真实密钥的局部变量截图分享。

修改 Python 代码后重启后端；修改 Vue 后开发服务器会更新，生产预览则需要重新 build。报错时先记下 request_id，在 `.local/backend.log` 查到状态，再根据错误码检查配置与目标服务。

本轮还通过浏览器测试发现并修复了数值输入步长导致的表单提交问题。这说明“后端测试通过”不能证明“用户一定能点保存”，两层测试都必要。
