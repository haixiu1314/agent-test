## 在当前电脑打开平台

项目已经安装好独立 Python 依赖和前端依赖，配置文件已生成。MySQL、后端和前端在交付检测时均已启动；如果浏览器能访问，直接进入 <http://127.0.0.1:5173> 即可。

重启电脑后，依次操作：

1. 打开 PowerShell，输入 `cd E:\Project-xhb\ai-test`。
2. 执行 `.\scripts\start-mysql.ps1`，启动项目自己的 3307 数据库。若端口已使用，脚本不会重复启动。
3. 执行 `.\scripts\start-backend.ps1`。窗口显示 Uvicorn running 后保持窗口打开。
4. 另开一个 PowerShell，同样进入项目目录，执行 `.\scripts\start-frontend.ps1`。
5. 浏览器打开 <http://127.0.0.1:5173>。

若 PowerShell 的执行策略阻止脚本，可以仅针对当前 PowerShell 窗口运行 `Set-ExecutionPolicy -Scope Process Bypass`，随后重试。不要修改整台电脑的执行策略。

停止前后端：在各自窗口按 Ctrl+C。停止项目数据库：

```powershell
.venv\Scripts\python.exe scripts\stop-mysql.py
```

该命令只关闭项目的 3307 实例，不关闭原 MySQL80 服务。停止数据库前先停止后端。不要删除 `.local/mysql-data`；其中保存真实业务数据。

## 注册和登录

在登录页点击“没有账号？创建账号”。用户名使用 3–50 位英文字母、数字、下划线或短横线；密码 10–128 个字符。注册后返回登录。

登录有效期为两小时。Token 保存在当前标签页的 sessionStorage 中；退出或关闭会话后重新登录。普通用户只能访问自己的项目和 Agent。

没有预设管理员账号。需要管理员时，先注册，再由电脑所有者在本地执行：

```powershell
.venv\Scripts\python.exe scripts\promote_admin.py 你的用户名
```

此脚本不是网页功能；不要向普通平台用户开放本机配置和脚本访问权。

## 接入自己的 HTTP Agent

先确认你的 Agent 能通过 HTTP 接口独立调用，然后创建 HTTP Agent 配置。例如待测接口接收：

```json
{"model":"your-agent","payload":{"question":"你好","history":[]}}
```

响应为：

```json
{"data":{"answer":"你好，我可以帮助你。"}}
```

平台中填写：

| 字段 | 填写值 |
| --- | --- |
| 地址 | 你的真实接口地址，例如 http://127.0.0.1:8001/chat |
| 方法 | POST |
| 参数模板 | `{"model":"your-agent"}` |
| 输入字段路径 | `payload.question` |
| 输出字段路径 | `data.answer` |
| 历史字段路径 | `payload.history` |
| 鉴权请求头名称 | 例如 `Authorization` 或 `X-API-Key` |
| 鉴权值 | 按服务要求填写完整值，例如 `Bearer ` 后加自己的密钥 |

路径目前支持对象字段的点分形式，不支持数组下标。输出映射必须指向字符串。GET 请求把参数模板发送为查询参数，其中嵌套对象/数组会序列化为 JSON 字符串，需和你的 Agent 协议相符。

不要把密码、API Key 放在接口 URL 或参数模板中；URL 内的账号密码和查询参数会被拒绝。鉴权值和自定义请求头值加密存库，不回显。

编辑时，鉴权值留空代表保留；勾选清除则删除。自定义请求头留空保留，填写 JSON 对象会替换全部自定义请求头，勾选清除则全部删除。

默认不重试。只有确认目标接口没有删除、转账、发消息等副作用时，才开启重试。平台只重试网络异常、超时和 502/503/504；不会自动跟随重定向。

连接结果只显示是否取得符合映射的输出、耗时和请求次数，避免回显上游敏感内容。工具事件标为“不可观测”。失败请求的尝试次数当前显示“—”，不要当作零次。

## 查看版本

修改 Agent 配置并填写版本说明后保存，再点击“版本”。旧版本快照保持不变。若两个页面同时编辑，过期版本保存时会提示刷新，防止覆盖别人刚刚提交的配置。

## 查看运行状态与日志

“运行状态”检测服务存活及 MySQL 迁移表可读性。它不会把数据库连通当作 Milvus 或 AI 模型可用。

- 后端日志：`.local/backend.log`，按大小轮转，最多保留三个备份。
- MySQL 日志：`.local/mysql-error.log`。
- 请求错误里带 request_id，可在后端日志搜索。
- API 文档：<http://127.0.0.1:8000/docs>；点击 Authorize 输入登录后取得的 Bearer Token 调试。

不要把 `.env`、`.local/mysql-admin.json` 或完整配置截图公开分享。

## 迁移到其他电脑时

当前电脑已安装完毕，不需要重复执行初始化。新电脑上先准备 Python 3.12、符合 Vite 要求的 Node（本轮为 24.22.1）和 npm，再执行：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install --no-cache-dir -r backend\requirements.lock
.venv\Scripts\python.exe scripts\init_local_config.py
```

在本地 `.env` 填写新的 MySQL 专用连接，或在安装 MySQL 程序后运行 `scripts/init_mysql.py` 创建项目实例。该脚本对已存在的数据目录拒绝重新初始化。

```powershell
cd backend
..\.venv\Scripts\python.exe -m alembic upgrade head
cd ..\frontend
npm ci
npm run build
```

`.tools` 是本机工具缓存，不在源码交付范围。新电脑有完整 npm 时直接使用 npm 命令。依赖安装曾因默认 pip 缓存写入卡顿，已通过 `--no-cache-dir` 解决，无需关闭 TLS 校验。

## 常见排错

| 提示 | 处理 |
| --- | --- |
| 端口 8000/5173 已使用 | 检查是否已启动同一服务，先访问现有地址；不要杀死不认识的进程 |
| 数据库不可用 | 检查 3307 实例、`.env` 和迁移；不要改动原 3306 的密码 |
| 登录频率受限 | 单来源认证操作 15 次/分钟；等待一分钟后重试 |
| 连接超时 | 检查目标 Agent 启动状态、网络、鉴权和超时设置 |
| output_field_missing | 响应 JSON 中找不到配置路径，核对真实返回字段 |
| output_must_be_string | 输出字段指向数字/对象，改为最终文本字段 |
| invalid_json_response | 目标返回 HTML/纯文本而非 JSON，检查接口地址 |
| 配置版本已变化 | 关闭编辑、刷新 Agent 列表，再重新编辑 |
| 修改密钥后旧配置无法解密 | 检查 ENCRYPTION_KEY 是否误改；恢复原本机密钥，不能随意重新生成 |
