## 2. 不配模型也能先学的流程

1. 选择项目，新建知识库，名称填写“客服制度实验”。暂时保留默认分块设置。
2. 本地新建 UTF-8 文件 `保修制度.txt`，写入“产品 A 的保修期为一年。有效期至：2020-12-31。”，复制为 `保修制度副本.txt`。
3. 在“文档与分块”批量选择这两个文件。页面逐个上传，显示各文件成功或失败，失败不会把其他文件伪装成成功。
4. 文档状态“已解析”只表示文本已保存。点击“查看分块”，核对文本、来源和页码。
5. 打开“知识质量”，先运行规则检查。可看到重复、明确有效期已过等问题。打开来源，比较两个片段，再选择人工确认或忽略。
6. 再上传只有“会议日期：2020-12-31”的文档，验证普通日期不会直接被判为过期。
7. 打开“问题集”，手工创建下面的 JSON。保存后可以重新打开编辑。
8. 未配 Embedding 时点击“建立索引”应看到配置错误，文档不能变成已索引。未配聊天模型时 AI 生成或评估会记录失败，不能出现编造分数。

问题集 JSON：

```json
[
  {
    "question": "产品 A 的保修期多久？",
    "reference": "产品 A 的保修期为一年。",
    "source_chunk_ids": []
  }
]
```

`question` 是测试问题，`reference` 是你认可的标准答案。手工问题可暂不填来源 ID；有来源时必须属于当前知识库。问题和答案都不能为空，一组最多 20 题。

## 3. 补齐真实模型与 Milvus 后的流程

本轮没有要求你现在配置模型，以下供稍后使用。密钥只填本地配置，不发在聊天中。

在项目 `.env` 填写服务商支持的 `LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY` 和 `EMBEDDING_MODEL`，更改后重启后端。该默认方式要求聊天和向量服务共用兼容接口与凭据。需要不同服务商时，可由管理员在“模型配置”分别创建 Embedding 和 RAG 用途模型，在知识库及评估界面选择。沿用已有管理员配置流程，不要直接改数据库授权。

Milvus 部署文件在 `deploy/compose.yaml`，先保证 Docker Desktop 引擎可用，再按第一阶段操作文档启动本地 Standalone。当前机器的 Docker 引擎管道尚不可用，本轮实际 Milvus 探测失败。不要反复点击索引尝试绕过环境问题。

向量维度必须与 Embedding 模型实际输出一致。例如模型输出 1024 个数，就填 1024；不要猜测。当前范围 8–4096。同一个 Milvus 集合固定维度，不同维度模型不能混用已有集合。

真实使用步骤：

1. 给知识库选择可用的 Embedding 模型，确认向量维度。
2. 上传文档并逐个建立索引。只有状态为“已索引”的文档参与检索。
3. “检索与评估”输入问题，选择 Top-K（1–10），查看命中的片段、来源和分值。相似度不是答案正确率。
4. 在质量页启用语义分析并选择 RAG 模型。系统用向量找候选，再让模型判断同一事实是否冲突；模型建议仍需人工核查。
5. 在问题集页生成 AI 草稿，逐题核对问题、标准答案和引用来源，编辑并保存后才能用于评估。自动生成不是人工审阅。
6. 选择已保存的问题集及评估范围。检索模式输出 Context Precision/Recall；回答模式也会先检索，再生成回答，输出 Faithfulness/Answer Relevancy；组合模式输出四项指标。
7. 打开评估历史，核对每题命中片段、实际回答、指标、错误码、模型及文档哈希快照。低于 0.7 会标记低质量，这是本项目的提示阈值，不是行业统一合格线。

## 4. 状态与限制

| 状态或情况 | 含义与处理 |
| --- | --- |
| 已解析 | 文本及分块已保存，尚不能证明向量写入成功 |
| 索引中 | 正在调用 Embedding 和 Milvus，同库其他操作会收到忙碌提示 |
| 索引失败 | 查看错误；部分外部向量可能存在，但不参与检索，重建或删除会尝试清理 |
| 草稿 | AI 问题需要人工核对并保存 |
| 评估部分完成 | 有题目失败，已得到的命中、回答和指标继续保留 |
| 服务重启中断 | 进行中的索引、问题生成和评估被标记失败，不会伪装完成；检查后重新运行 |
| 删除返回 503 | 向量清理失败，保留 MySQL 元数据供重试，不代表已删干净 |

单文件实际大小最多 500000 字节；一次前端选择最多 10 个文件；每库最多 100 文档。TXT/MD 需 UTF-8。PDF 最多 100 页，不支持加密文件或 OCR 扫描识别；DOCX 解析段落和表格，不执行宏，其页码为逻辑页 1，并非 Word 排版页。DOCX 解压最多 10MB/2000 条目；提取文本最多 100 万字符，单文件最多 1000 块。文本使用 NFKC 和空白规范化，因此全角标点可能变化。

分块长度 100–2000 字符，重叠必须小于长度。已有文档后不能直接更改分块参数；尝试建立索引后不能随意更改向量配置，应新建知识库验证新方案。

质量检查每次最多覆盖 300 块，结果会说明覆盖范围。规则相似候选只比较前 500 字符；语义候选最多送审 20 对；AI 生成问题只取最多 30 个分块。它们不是全库穷尽扫描。质量语义分析和批量评估有 180 秒工作流预算，大数据请分库或分批。当前运行方式是单后端进程，知识库互斥并非分布式锁，不要直接启用多 worker。
