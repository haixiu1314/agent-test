# 第一阶段界面检查

采用 design-taste-frontend 的 app-screens 流程。方向：framed-sheet，seed 46761458，无重抽；使用蓝灰框架、白色工作区及深蓝操作色，系统 Segoe UI / 微软雅黑字体，保留需求中的中文、左导航和专业平台风格。

产品特征：实验室烧瓶线形标记；Agent 行中明确列出协议、字段映射、版本、超时和密钥配置状态。没有使用外部照片、图标库图片或虚构统计。

页面问题：

- 登录：如何进入自己的测试空间？主要操作为登录/注册。
- 项目：我要在哪个业务范围接入 Agent？主要操作为创建项目。
- Agent：哪些目标已配置，连接是否成功？主要操作为接入和测试连接。
- 状态：服务和数据库现在是否可用？分别检测，不用一个绿灯代表所有依赖。

## 检查工具与限制

技能 lint 初次通过；格式化后出现 `box-shadow: none` 的误报，已移除该冗余规则，最终以实际 lint 输出为准。

原技能 inspect 分别尝试 Chrome 与 Edge，均在 CDP `Page.enable` 超时，未产生有效测量报告。不能宣称 inspect 的 0 FAIL 已通过。

替代验证使用项目安装的 Playwright 和本机 Edge，访问生产构建预览。`frontend/scripts/visual-check.mjs` 记录项目、Agent、状态三个页面在 1440/768/390 宽度的九组测量，检查横向溢出、唯一 h1 和可见小字。另保存登录页三种宽度截图。

此替代检查没有覆盖技能 inspector 的全部规则，例如完整对比度与逐字字体加载检测；不与技能 inspector 等价。

## ROUND 1

Seen in one second：中文 Agent 接入列表与连接结果。

Idea：把接入协议、配置版本和真实连接结果放在同一工作空间。

Live thing：真实创建项目、保存配置、调用适配器、读取历史版本。

Layout：登录=左右分栏；项目=列表与入门指引；Agent=配置列表与连接结果；状态=逐项检查。

主要问题与修复：

1. 首次浏览器截屏发生在对话框关闭动画期间，叠加多条成功消息；测试改为等待对话框隐藏且消息消失后截图，不将动画中间态当作最终界面。
2. 768px 登录标题出现单字尾行；精简标题为“智能体测试空间”。
3. 长 HTTP 配置表单超出首屏；对话框内部限制高度并允许滚动，保存操作可达。

浏览器业务测试同时发现并修复了下拉文字挡住输入点击、超时数值 min/step 不匹配导致保存被原生校验阻止的问题。

截图：`docs/evidence/login-*.png`、`projects-*.png`、`agents-*.png`、`system-*.png`。
