# AgentTestLab 全功能操作与验收手册

更新：2026-11-08。项目根目录：`E:\Project-xhb\ai-test`。本文面向初学者，按顺序操作即可检查项目。所有相对路径都以项目根目录为起点。

## 0. 先读懂“通过”

项目原计划七个阶段，前四阶段已有代码，本次连续补齐第五至七阶段：安全测试与轨迹、质量报告与回归、个人中心和交付资料。**代码已覆盖这些模块，但不能据此认定所有真实 AI 功能已经验收通过。**

当前真实 MySQL 与本机协议目标可以验证；聊天/Embedding 配置仍缺失，Milvus 实际探测失败。你可以先完成不需要模型的操作，再配置外部服务完成 AI 项。测试替身、协议服务、模拟天气都不是实际 AI 能力的证据。

本文约定：

- “平台检查通过”：实际结果符合本条预期。比如反向用例显示“失败”，恰恰说明平台正确找到了问题。
- “待判定 / unknown”：缺模型或证据，不能当作通过。
- “已完成任务”：调度结束，不表示每条用例都通过。
- “实测状态”：由开发验收证据证明的范围；真实 AI 项目前标为待补验，手工完成后再勾选。

建议每次验收使用新的项目名称，例如“我的完整验收-20261104”。记下项目、任务、报告 ID，保留截图与导出文件。不要删除故意失败的记录，否则无法验证缺陷和回归功能。

## 2. 单终端启动

日常使用，只需要在项目根目录运行：

```powershell
cd E:\Project-xhb\ai-test
npm run dev
```

命令自动验证数据库、升级表结构、启动后端和前端，并打开默认浏览器。终端显示前端 <http://127.0.0.1:5173>、API 文档 <http://127.0.0.1:8000/docs> 和健康检查 <http://127.0.0.1:8000/health/ready>。按 Ctrl+C 同时停止本次前后端，MySQL 服务保持运行。无需分别打开多个服务终端。

**首次按本手册做全功能验证时，使用下面的验收模式代替普通启动：**

```powershell
npm run dev:verify
```

它在同一个终端额外启动 8001 非 AI 协议目标，供后文基础用例、安全策略和版本回归使用。不要同时运行 dev 和 dev:verify；切换前先 Ctrl+C。协议目标仅模拟工具事件，不会执行删除、转账或发消息，也不证明实际 AI 能力。8001 只接受 POST，浏览器直接访问出现方法错误是正常情况。

预期结果：终端出现 `AgentTestLab ready` 和访问地址；前端可打开，health/ready 返回 database=ok。终端 `Database:` 显示实际库名；完成切库后应为 localhost:3306/agenttest，目前尚未切换则仍为 127.0.0.1:3307/agenttestlab。

3306 的 MySQL Windows 服务应先保持运行。若仍用旧 3307 配置，启动器会在必要时启动项目私有实例。连接错误时明确退出，不会显示启动成功；端口占用时不会自动杀其他程序。根目录 npm 脚本不需要新依赖。若 PowerShell 阻止 npm.ps1，使用 `npm.cmd run dev` 或 `npm.cmd run dev:verify`。

保持启动终端运行；后续需要输入验收命令时，另开一个“验证终端”即可，不再分别开前后端和协议服务窗口。不自动开浏览器可加 `-- --no-open`。

本机 Python 通过 `scripts/run_module.py` 加载 `runtime-packages`，请保留这两个目录。`.env`、`.local/mysql-admin.json`、`deploy/.env` 及 `.local/*.backup` 含本机凭据，不分享、不提交 Git。

## 6. 创建与执行基础任务

在“测试执行”选择本机协议 Agent、基础验收套件，创建名为“基线-v1”的任务。选择当前 Agent 版本、套件修订，并发 1、超时 5 秒、重试 0 次。执行用例留空表示执行套件全部用例。点击开始。

**预期结果：总数 2，通过 1，失败 1，完成 2；任务状态已完成。** 正向用例包含 42；反向用例故意要求不存在的文字，因此应失败。结果详情包含输入、实际回答、规则检查、真实响应时间、调用次数和工具事件；协议目标未提供 Token 数值，因此 Token 应是“—”，不能自动填 0 或 7。

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| D01 | 查看结果详情并刷新 | 判定和原始回答一致，刷新不丢历史 |
| D02 | 创建只选择正向用例的新任务 | 总数 1，正常 v1 下通过 |
| D03 | 对基线任务“失败重跑” | 新任务仅包含原来非通过的用例，不改写旧结果 |
| D04 | 编辑 Agent 请求模板为 `{"mode":"http_error"}` 后创建任务 | 本机目标确实返回 503，平台显示异常/目标调用错误，不能当作通过 |
| D05 | 模板改为 `{"mode":"slow"}`，超时设 1 秒，重试 1 次 | 调用约 1 秒超时后重试；总尝试数 2，保留超时/重试事件，最终异常 |
| D06 | slow 模式，超时 5 秒，用至少 6 条复制用例并发 1；开始后立即暂停 | 在途用例完成后停止领取新用例，状态已暂停，pending 保留；继续后完成 |
| D07 | 再建同样慢任务，运行后终止 | 在途结束后不再领取新用例，剩余标为已取消；取消不计通过 |
| D08 | 慢任务运行时在本项目启动终端按 Ctrl+C，再重新执行 npm run dev:verify | 启动将运行中记录标中断；可继续未完成部分，原已完成结果保留 |
| D09 | 选择旧 Agent 版本再次执行 | 读取旧快照；不因当前编辑器模板变了就偷偷改用新配置 |

做完把 Agent 模板改回 `{"mode":"v1"}`。慢任务的暂停/终止是调度边界控制，不保证已发给目标的调用立即停止。单进程最多 3 个活跃任务，每任务并发 1–10，不能直接开多个 worker 共用当前执行器。

实时进度页面每 1.5 秒轮询；鉴权 SSE 进度也由后端提供。需要核验 SSE 时运行第 15 节的 `verify_stage3_mysql.py`，其验收项包括 authenticated_sse；不要把 token 放进公开 URL。

## 8. 安全测试，不配模型也能验证的部分

新建安全专用套件，导入 `docs/examples/全功能验收-安全用例.json`。将本机 HTTP Agent 的模板改为 `{"mode":"unsafe"}`，保存为新版本。

进入“安全测试 → 执行与风险”，选择该 Agent 和安全套件，创建隔离安全任务并开始。此声明仅适用于你控制的隔离目标，不能用于测试未授权外部服务。

**预期结果：** 协议目标只返回模拟 delete_file 事件，没有真实删除。平台根据 forbidden_tools 检测实际收到的禁止工具证据，风险 high、违规 yes、结果失败；原因指向工具策略。缺 judge 模型时语义评估仍不可用，但已发生的工具策略违规不能被它覆盖。查看证据可看到攻击输入、实际回答、工具事件、原因和建议，轨迹链接能打开原结果。

再把 Agent 模板改为 v1，建立新的安全任务。**没有 judge 模型时预期待判定、风险 unknown、违规 unknown，而不是“安全通过”。** 不应仅凭回答包含“拒绝”就认定安全。

其他检查：

- 安全任务若选了混有普通用例的套件，应拒绝。
- 没有声明隔离目标的 API 安全任务请求应拒绝；远程 HTTP 地址也应拒绝，本机地址以外不开放。
- 创建安全报告后，高危违规独立红色提示；它不能被其他高分掩盖。
- 八个类别均可在生成页选择：提示词注入、越狱、角色操纵、敏感信息泄漏、工具误用、过度自主、知识投毒、多轮攻击。真正自动生成与语义结论按第 9 节补验。

## 9. 配置真实模型与自动生成用例

**每个登录用户都能配置自己的模型。** 打开 `/models`，填写配置名称、用途、模型URL、准确模型名称和API密钥；眼睛按钮可以显示/隐藏本次输入。点击“测试”，通过后保存；修改表单后需重新测试。测试真实请求所填服务，可能消耗少量额度。编辑时密钥留空可继续使用原值，已保存密钥不回显。每个账号只可查看、编辑、测试和引用自己的配置。

聊天连通测试固定单字符输入、最多1个输出token且不自动重试，向量测试固定单字符输入；页面不提供参数调节。详细操作和失败预期见 [个人模型与账号使用说明](个人模型与账号使用说明.md)。

LLM_BASE_URL=你的兼容服务地址
LLM_MODEL=聊天模型实际名称
LLM_API_KEY=仅填本地真实密钥

修改 `.env` 后重启后端。默认模式要求聊天和向量共用兼容服务与凭据；若不同服务商，每个已登录用户都能在“模型配置”分别创建自己的 generation、demo、judge、security、rag、embedding 用途配置。模型用途必须匹配，不能把 Embedding 配置选作聊天生成模型。页面只返回密钥是否存在，不回显真实密钥。

## 16. 出错时如何判断

| 现象 | 先看哪里 | 处理 / 应保留的证据 |
| --- | --- | --- |
| 页面连不上 | 统一启动终端、8000/5173端口 | 先启动服务，不重复启动或乱杀进程 |
| 401 | 登录与会话 | 重新登录，token不发聊天 |
| 403 | 当前角色 | 用正确账号，管理操作必须admin |
| 404 | 资源ID与账号归属 | 确认项目，不绕过归属检查 |
| 409 | 修订号、忙碌状态、模型缺失 | 刷新/等待/补配置，不能忽略错误强写 |
| 422 | 必填字段、JSON、数量、格式、维度 | 对照字段修正；错误不回显敏感输入 |
| 429 | 登录限流或任务上限 | 登录最多每来源15次/分钟，等待；活跃任务最多3个 |
| 502/503 | 外部Agent/模型/Milvus、数据库 | 先排外部服务，记录错误码与请求ID；不当通过 |
| 分数—或unknown | 模型/contexts/轨迹 | 缺证据就补齐后重跑，不补假分数 |
| 日志里uvicorn.error | 日志级别 | 这是logger名称，INFO启动行不是ERROR |

后端日志：`.local/backend.log`；旧3307实例日志：`.local/mysql-error.log`，3306日志在系统MySQL配置指定位置。凭请求ID定位，不把含密钥的配置或原始日志直接发出。
