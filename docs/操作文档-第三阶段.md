## 2. 先体验不需要模型的完整流程

1. 在“测试项目”创建项目，例如“我的执行实验”。
2. 在“Agent 接入”创建 Agent，接入方式选择“受控 Python 协议验证（非 AI）”，适配器选择“协议回显”。它只是返回带有原输入的文本，不能用于证明 AI 能力。
3. 在“测试用例”选择项目、创建套件，并新增功能测试用例。填写名称、场景、用户输入“你好”、预期行为“回应输入”、预期结果“包含你好”。
4. 判定方式选择规则，在规则 JSON 中填写 `must_include: ["你好"]`。保留 `evaluators: ["rules"]` 和非空 `rubric`。
5. 再建一条用例，要求包含“绝不会出现的内容”，用来观察失败。
6. 打开“测试执行”，选择项目，点击“创建任务”。
7. 选择 Agent、套件及版本，执行用例留空表示全部执行；也可以只选一条。填写并发数、超时和重试次数，保存任务。
8. 点击任务行的“开始”。页面每 1.5 秒刷新进度。点击任务名称或“查看结果”，查看每条结果。
9. 点击“结果详情”，核对输入、实际回答、评估依据和执行元数据。

规则 JSON 的完整示例：

```json
{
  "evaluators": ["rules"],
  "rubric": "回答包含用户问候，响应不超过五秒",
  "must_include": ["你好"],
  "must_not_include": [],
  "max_latency_ms": 5000,
  "max_attempts": 1
}
```

“预期结果”的文字不会自动变成关键词规则。只填预期结果、没有可执行规则的用例，会显示待判定。需要语义判断时应选择 `llm_judge` 并配置模型。

## 3. 理解结果

| 显示 | 含义 | 接下来做什么 |
| --- | --- | --- |
| 通过 | 所选评估器都通过 | 查看依据是否符合测试目标 |
| 失败 | 至少一个判定未满足预期 | 对照实际回答与规则排查 |
| 异常 | Agent 调用、超时或评估过程出错 | 查看错误码、配置和日志 |
| 待判定 | 缺少模型、规则或可观测证据 | 补齐后重跑，不能当作通过 |
| 已取消 | 没有继续执行的用例 | 按需要创建重跑任务 |

任务“已完成”表示调度结束，不代表所有用例通过。进度统计包括失败、异常、待判定和取消。

响应时间包含目标调用及其重试等待，不包含后续评估模型耗时。Token 只展示目标 Agent 实际提供的数据；没有提供时显示“—”。工具次数只依据目标可观测事件，不能靠回答文字猜测。

## 4. 暂停、继续、取消和重跑

- **暂停**：停止领取后续用例，等待正在执行的用例结束后显示“已暂停”。当前用例会保存结果。
- **继续**：执行剩余待执行用例，保留已经完成的结果。
- **取消**：同样等待在途用例完成，后续用例标记已取消。不是立即中断远端工具。
- **重跑未通过**：创建新任务，仅包含失败、异常、待判定或未完成的用例，仍使用原任务版本快照；历史任务保留。
- **重启恢复**：启动时将运行中任务标为已中断。点击“继续”会执行未完成和中断的条目，不重复执行已经完成的条目。

如果远端 Agent 在断线前已经执行了外部动作，重试可能再次触发动作。业务工具应支持请求幂等或使用独立测试环境。本平台目前无法保证跨服务动作恰好执行一次。

每任务并发 1–10，同时最多运行三个任务。单次目标调用超时 1–180 秒，最多追加重试三次；Agent 自身配置的超时也会生效。模型评估另有 180 秒整体保护。

## 5. 接入你自己的 HTTP Agent

“Agent 接入”填写实际地址与字段路径。例如目标响应：

```json
{
  "data": {"answer": "计算结果为 2"},
  "usage": {"total_tokens": 30},
  "events": [
    {"type": "tool_result", "name": "calculator", "arguments": {"expression": "1+1"}, "success": true, "result": {"value": 2}}
  ]
}
```

输出字段填 `data.answer`，Token 用量字段填 `usage`，工具事件字段填 `events`。没有事件字段时留空，平台明确记录为不可观测。可选的实际检索上下文字段必须对应字符串数组。

鉴权值使用页面加密字段，不写在接口 URL 和请求模板中。修改配置会创建新版本；任务创建后固定版本，后续编辑不会影响旧任务。

## 7. 自动验证和排错

确保没有其他测试任务在运行，再运行：

```powershell
cd E:\Project-xhb\ai-test
.\scripts\check.ps1
.venv\Scripts\python.exe scripts\run_module.py scripts\test_migrations.py
```

`check.ps1` 需要后端和前端服务都已启动。它会创建独立测试账号和业务数据，保留证据。旧阶段的 MySQL 验证会创建新应用并执行启动恢复，因此不要在真实任务运行期间运行验收脚本。

| 现象 | 原因与处理 |
| --- | --- |
| 创建按钮不可用 | 当前项目缺 Agent 或套件；空套件需先添加用例 |
| 返回 409 | 状态不允许操作，或控制请求尚未完成；刷新后重试 |
| 返回 429 | 同时已有三个运行任务；等待或暂停后再启动 |
| 评估不可用 | 模型未配置、规则为空或 Agent 未提供工具事件 |
| case_timeout / upstream_timeout | 检查目标响应、任务超时及 Agent 超时 |
| 数据库 503 | 检查 3307 实例和迁移版本，不要删除数据目录 |
| 端口 8000/5173 被占用 | 已有服务运行；使用现有服务，或在它原来的终端按 Ctrl+C 后重启 |
| pytest 临时目录拒绝访问 | 使用项目 `.local` 下的 `--basetemp`；参考 check.ps1 |

后端日志：`E:\Project-xhb\ai-test\.local\backend.log`。错误响应带请求编号，可用编号查找日志。日志不输出密钥、请求正文或模型异常原文。
