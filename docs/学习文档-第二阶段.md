# AgentTestLab 第二阶段学习文档

建议先按操作文档创建一条人工用例，再从本文追踪它怎样保存。不要先啃所有 AI 代码。

## 1. 这次增加的几个概念

项目像一个文件夹；套件是文件夹中的一组试题；用例是一道写清输入、预期结果和判定方法的试题；生成草稿是模型写出的候选试题。草稿需要人审阅，不能直接当成可靠测试资产。

修订号是乐观锁：页面看到 v2，提交时带上“我编辑的是 v2”。如果数据库已经是 v3，后端返回 409，要求刷新，避免把别人的修改覆盖掉。MySQL 的行锁负责让同时到达的两个请求依次检查修订号。

不可变快照像保存一次完整存档。修改用例会新增套件版本，旧版本仍保存当时的内容。这为后续回归比较提供基础；当前尚未实现版本回放执行。

## 3. 从“保存用例”追踪一次请求

1. `Cases.vue` 将普通表单字段与高级 JSON 组合，调用 `POST /api/v1/cases?expected_revision=...`。
2. Axios 在 `frontend/src/api.ts` 自动附加登录 token。
3. FastAPI 的 `current_user` 验证登录；`CaseCreate` 检查字段，拒绝伪造 `source=ai`。
4. `suite_for_user` 找套件，验证项目归属，锁定套件行并比较修订号。
5. `add_cases` 插入用例；`snapshot` 增加套件修订号、保存当时全部用例。
6. `audit` 在同一个事务写操作日志并 commit。失败时 session 关闭会回滚，不留半批数据。
7. API 返回公开用例字段，Vue 刷新列表和最新修订号。

输入是一个 JSON 对象，输出是带 ID、来源、修订号和时间的 JSON 对象。看到列表就能证明当前接口可读；还需重启应用或重新建立连接读取，才能验证持久化不依赖内存。

## 4. 为什么不只用关键词判断

模型可能没有查天气，却碰巧回答“晴”；没有调用计算器，也可能猜对 50。因此工具用例还要记录工具名称、参数、调用成功和回答是否基于工具结果。安全用例需要明确的安全策略和语义判断，记忆用例需要真实历史对话，RAG 需要检索上下文与专业评估。

本阶段 `Rules` 只要求保存这些依据。它们是未来执行引擎的输入，不是已经计算出的分数。`evaluators` 中的 `deepeval/ragas` 名称不代表这些评估器已运行。

## 5. AI 生成的完整路径

`Generate.vue` → `POST /generation-runs` → `resolve_model` → `ChatOpenAI.ainvoke` → `GeneratedBatch` 校验 → 待审阅记录 → 用户编辑/勾选 → `/generation-runs/{id}/save` → 用例与快照。

LangChain 把模型消息、工具调用和供应商接口封装成统一对象，减少各处重复写网络请求。`ChatOpenAI` 在这里表示 OpenAI 兼容协议的适配器，也可以配置兼容服务商；不表示写死某个模型。

模型仍可能写错 JSON、漏字段、少生成某种类型。系统用 Pydantic 解析完整响应，再检查数量和类型覆盖；失败会保存失败状态，不能当成有效草稿。没有自动修复重试，也没有预制用例降级，避免用户误把静态内容当作模型产物。

状态路径：`generating → review → saved`，失败为 `failed`。`saved_indexes` 记录哪些原始草稿已入库，防止重复点击产生重复用例。编辑后用例在套件快照保存，原始模型草稿仍可追溯。

原始模型响应加密保存；token 用量只记录服务商实际返回的数据，没有返回时保留空对象。当前没有费用估算或 token 统计看板。

## 6. 演示助手为什么能调用工具

模型收到 `TOOLS` 定义后，可以返回工具调用请求。服务器只执行白名单中的 calculator、weather、knowledge_search，把实际结果作为 `ToolMessage` 传回模型，再获取最终回答。最多四轮模型响应、每轮五个工具调用，整体最多 120 秒。

`calculate` 使用 Python AST：先把算式解析成语法树，只接受数字、正负号、加减乘除；没有 `eval`，不执行上传代码。输入长度、树节点数和数值范围也有限制。对任意表达式调用 `eval` 会带来代码执行风险，因此不能用它替代。

天气固定模拟。知识库只有两段人工样例，按关键词筛选，没有 embedding 或向量相似度，因此不能当作完整 RAG。缺陷模式改变真实执行的工具描述、样例内容或返回错误，用于以后检验评估器能否识别问题。

事件只包含真正观测到的模型响应时间、工具参数和工具结果。没有虚构内部推理链，也还不是后续完整轨迹审计模块。

## 7. 密钥、事务与字段容量

`SecretVault` 用 Fernet 对密钥和演示载荷加密。加密需要长期保留 `.env` 中的加密密钥；丢失后无法读取既有密文。API 只返回 `has_api_key`，不返回密文或明文密钥。

MySQL 普通 TEXT 大约只能存 64 KiB；20,000 个四字节 Unicode 字符可达 80 KB，加密还会增加体积，所以长输入和模型/演示密文使用 MEDIUMTEXT。Pydantic 的字符上限、HTTP 请求字节上限、数据库字节容量是不同的限制。

CSV 需要保存嵌套对象和数组，每格采用 JSON 编码，避免随意用逗号拼字符串导致中文、换行、引号损坏。`import_cases` 在任何写入前验证全部行；`snapshot` 在一个事务里保存整批变化。

## 8. 如何调试和读测试

先运行 `backend/tests/test_stage2.py`，从 `test_case_lifecycle_versions` 和 `test_import_round_trip_atomic` 看起，再读生成和演示的测试。测试中的 fixture 模型是故意设置的替身，只验证流程与错误处理，不能证明模型生成质量。

`scripts/verify_stage2_mysql.py` 使用真实 3307 MySQL 检查行锁、导入和新应用读取；`frontend/tests/stage2.spec.ts` 使用真实浏览器操作页面；`scripts/verify_real_model.py` 才会调用 `.env` 中配置的真实模型。三者证明的事情不同，应分别报告。

后端调试可在 `generate`、`save_run`、`snapshot` 和 `execute_tool` 设置断点。前端用浏览器网络面板核对提交字段与响应状态；不要将包含 token 或密钥的请求截图公开。

常见错误可先按状态区分：401 检查登录，403 检查角色，404 检查归属和 ID，409 刷新版本/检查模型配置，422 检查输入格式，502 检查模型调用，503 检查 MySQL。具体命令和处理见操作文档。

## 9. 建议的学习练习

先导入人工模板，再手工修改一条；比较两个套件快照。用两页浏览器同时打开同一条用例，先保存第一页，再保存第二页，观察 409。尝试导入一条正确、一条缺字段的数据，确认数量不变。最后配置真实模型，观察一次工具事件，与只看回答的区别。

后续学习顺序是执行任务与评估器、RAG 文档和 Milvus、安全对抗、轨迹审计、回归与报告。当前不能把前两阶段代码当作整个平台已完成。
